## Dependency and merge strategy

This Stage 5 branch starts at #72's verified evidence head e2ff7ea and should be
reviewed as a small stacked **Draft PR against `experiment/wren-japanese-desktop`**.
It does not make the five experiments independently mergeable to main. #70
already contains #68/#69; #71/#72 depend on #70. Before any merge, choose the
reviewed lineage or extract the planned production commits onto main with an
explicit dependency manifest. Do not merge all experimental branches blindly,
rebase away physical artifact identities or overwrite historical measurements.
All five existing PRs stay Draft; no automatic merge is authorized.

## Risk register and current limits

| Risk | Current evidence / mitigation | Exit condition |
|---|---|---|
| Unresolved HDMI red outline | Historical #72 classifier still reports 46 pixels; 140-pixel geometry cross-check does not waive it. Initial UGREEN warmup issue recovered with longer capture, not a universal HDMI guarantee | Dedicated capture/color investigation with original thresholds; no claim resolved here |
| Unvalidated new physical artifact | Stage 5 has host/ARM/static evidence only. #72 physical stack/HDMI/restoration are historical | Separate exact-artifact hardware authorization and full acceptance/restoration |
| Limited contiguous SRAM | Main margin 24,036 B plus two separate 4,096 B scratch banks; not a 32,228 B contiguous heap | Per-PR linked address audit; retain 48 KiB stack and 8 KiB recovery |
| Stack evidence is workload-specific | Historical painted peak 33,848 B leaves 15,304 B reserved margin; emulator is not interrupt/USB worst-case proof | New calls/features require static frames, emulated stack and later physical high-water evidence |
| OOM nonlocal recovery | Existing longjmp discards VM and ledger, no foreign finalizers; arbitrary native callbacks could add cleanup obligations | Keep restricted boundary; audit any resources/foreign objects/finalizers before adding them |
| Shared scratch lifetime | Safe only with synchronous sink and no render reentry | Preserve busy/fault/ack tests; async design requires independent ownership proof |
| Experimental path coupling | New targets still reference old source/test/font paths; old CMake duplicates platform policy for reference comparison | Staged source moves and compatibility entry points, then centralize policy after equivalence |
| Header exposure | Native headers expose trusted internals; facade is a build boundary, not a hardened binary ABI | Keep Wren bindings narrow; review future opaque API only when needed |
| Native borrowed labels | Menus/icons/class/user pointers borrowed, unlike copied window titles | Explicit static/pool lifetimes and mutation contracts before script-accessible roles |
| Unicode input limitations | `kd_event.ch` byte and `kd_label` byte cells remain; display does not imply Japanese entry | Separate Unicode event/label API design; no FPGA ABI reinterpretation |
| Small GUI workload only | Current four-event/one-window Wren demo and native test cover are not general app capacity measurements | Define per-app limits; measure more applications without forcing all stress tests into normal budget |
| Fixed pool proposal limits | Two 256-byte blocks and finite classes may reject valid replacements | Demand/exhaustion tests; atomic rejection rather than hidden allocator or reserve borrowing |
| Reproducibility vs identity | Toolchain/path/debug metadata can change ELF SHA while load segments match | Compare exact PT_LOAD addresses/bytes and full map, record both hashes and tool pins |
| Test source reuse still has multiple builds | Native variants, old experiments and new facade compile common C under differing flags intentionally | Retain fault variants and frozen goldens; consolidate registration only after source migration, not delete tests |

No blockers prevent the minimal build-boundary step: the existing source
boundaries are already separable. The blockers above limit production readiness
and future features; they are not a reason to rewrite the validated renderer.
