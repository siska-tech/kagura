# PROJECT STARFALL 第5版 — 場面別BGM

2026-10-31、`feat/project-starfall`。診断firmware、MicroPython、RTLは変更していない。

## 曲と切替

すべてオリジナルの音列。BGMを`music.c`の決定的なスコア生成と、`audio.c`の
実レジスタ転送に分離した。ゲーム状態と場面の経過tickから曲・音程・音量・リズムを求める。

| 場面 | 曲名 / 雰囲気 | タイミング |
|---|---|---|
| タイトル | Dock lights / 落ち着いた短いarp | タイトル画面 |
| 宇宙 | Blue orbit / 明るいmajor、112.5 BPM | 開始〜1119tick |
| 基地接近 | Approach vector / 下降するminor、100 BPM | 1120〜1439tick |
| 基地内部 | Iron lattice / 短く刻むminor、150 BPM | 1440〜2639tick |
| 警告 | Lock-on warning / 交互2音と低いpedal | 2640〜2759tick |
| ボス | Siege engine / 速いdiminished、180 BPM | 2760tick〜ボス撃破 |
| 脱出 | Exit burn / 上昇するmajor | 撃破tickから、clearまで |
| クリア | Sector secured / 短いfanfare | clear後128tickで停止 |
| GAME OVER | Lost signal / 下降する終止 | game over後96tickで停止 |

BPMは固定60tick/sで1stepを16分音符相当とした設計値。
実機のHDMI周期が59.94Hzならその比率で遅くなる。
曲の切替では新しい曲のローカルtickを0から使い、最初の12tickで段階的にfade-in。
各frameで全BGM voiceの新しい状態を決めるため、旧曲の音を残さない。
クリア/GAME OVERはone-shot終端で全BGM voiceとpercussionを0にする。

## 音源と負荷

ch0 pulse melody、ch1 pulse arp、ch4 wave bass、ch5 wave pad。
ch2はpulse SFX専用。ch3はnoise percussionを基本とし、撃破/被弾SFXの間だけ譲る。
shot/power/warningなどpulse SFXの間はpercussionを継続できる。
SFX優先度は従来の被弾 > 警告 > 強化 > 撃破 > shotを維持する。
波形は従来のtriangleを両bankへ初期化し、曲の切替ではVRAMへ送らない。
変更されたregisterだけを書き、変更があれば1回AUDIO_COMMITする。
MASTER_GAIN=24は前版と同じ。

音源試験で観測した最大は1更新29 register writes（特定テスト列の観測値であり全状態上限ではない）。
SPI/QSPIの実転送量・BGM変更後のframe時間・音量は実機未測定。
ゲーム側の`wire_*`と`work_*`に音源更新を含み、`bgm`で現在の曲を表示する。
曲のための新しいOAM/VRAM/PSRAM予約はなく、前版のsprite上限と公開VRAM15200 Bは維持する。

## 検証と成果物

- C11、Wall/Wextra/Werror、ASan/UBSanのホスト4件PASS。
- 9曲の96frame分の音程/音量/音色/リズム列が互いに異なり、同じ状態からは同じ結果になることを検査。
- 1119/1120、1439/1440、2639/2640、2759/2760tickの境界を検査。
- 音程/左右gain/controlが実レジスタへ一致して送られること、終曲後の停止、SFX優先度、
  wave bankの保持、同じ設定なら再COMMITしないこと、I/O失敗時の停止、音源なしfallbackを検査。
- 既存のゲーム・mapストリーミング・入力のテストもPASS。
- 生成register/設計検査PASS。RTL変更なし。全RTL回帰/合成/STAは今回実施していない。
