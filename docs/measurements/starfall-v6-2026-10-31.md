# PROJECT STARFALL 第6版 — オプションレーザー・基地床修正・演出

2026-10-31、`feat/project-starfall`。診断firmware・MicroPython・RTLは変更なし。
ユーザーの実機報告を受けてゲーム側を修正した。新版の実機確認はまだ行っていない。

## オプションレーザー

旧版は1本のレーザーの発射元を自機/オプションで巡回しており、同時発射ではなかった。
停止中は履歴位置も一致し、支援機と自機の発射位置が重なりやすかった。
今版では3本までの独立した弾道と命中履歴を持ち、同じFIREイベントで自機＋全支援機から発射する。
支援機は遅延履歴に加えて12/24px後方、上下8pxへ配置し、描画と発射位置で同じ関数を使う。
自機は青、支援機は金色。各レーザーは1敵に1回3damage、地形で切れ、死亡/装備変更で消える。

走査線予算は先に自機・支援機・敵・敵弾・ミサイル・カプセルを全て予約する。
その後、各レーザーの先頭16pxを確保し、16px単位で順に最大64pxへ伸ばす。
予約できない長さは実際の命中範囲ごと短縮する。非表示の友軍判定や敵弾は作らない。
最悪の同一lineでは本体32px＋支援16px＋支援16pxとなるが、全発射元の先頭を残す。
混雑していない場所では3本とも64pxを表示できる。爆発・発射flashは最後に予約し、必要時のみ省略。

## 中央に混入した基地床

旧ラスタ帯はy48〜`height-48`で、下部HUDを分離した後の基地床を一部含んでいた。
map ringへ先行配置された画面外の基地列が、低速スクロール帯から中央へ見えるケースを再現した。
帯の終端を`HUD_TOP-48`へ変更し、将来の床の最上位置より8px上で止める。
480p論理240では終端168、720p論理180では終端104。
入口到達後は従来どおりrasterを無効化し、表示と衝突を同じ通常scrollにする。

回帰試験ではtick936〜1119を4tick間隔、表示内4px刻みで検査。
旧設定の床混入サンプルは180モード1356件、240モード432件、修正後は両方0件。
これは同じmap/raster座標を使ったホストでの再現件数であり、実機で数えたpixel数ではない。

## 敵・演出

- 赤い旋回迎撃機、可動翼glider、急降下機へオリジナルのspriteを描き直し、2frameでアニメーション。
- 旋回機は編隊進行後に緩く曲がり、急降下機は出現後に自機の高さを捉えて加速する。
- 砲台は砲身・ドーム・台座を持つ形へ変更。天井配置は全体を上下反転。
- ボスは射撃前にcoreが発光し、時間差の3連射。被弾中は白くflashする。
- 自機のengineと支援orbの明滅、発射flash、爆発の白い初期burstを追加。
- 基地隔壁へ配管/ventを追加。侵入・警告時はHUDを橙色に点滅させる。
- 第5版の場面別BGMを維持。敵AIや武器変更で音源・RTLは変更しない。

## 使用量

| 項目 | 値 |
|---|---:|
| Pattern予約 | 320×32 = 10240 B（番号0..319） |
| BG tile番号 | 0..255のみ。列転送は従来どおり低位byte、INC128 |
| Palette | 4本128 B。追加1本は被弾flash |
| Map / upper / OAM予約 / wave | 4096 / 256 / 2048 / 512 B |
| 公開VRAM予約合計 | 17280 B |
| 管理OAM / 最大line | 64枠512 B / 16 sprite |
| ゲーム状態 / frame | 660 / 520 B（ホスト） |
| ELF text / data / bss | SPI/QSPIとも98532 / 0 / 17364 B |
| CPU0 stack予約 | 4096 B、ELF StackBottom=0x20041000、StackTop=0x20042000 |

GCCのstack-usage出力で`sf_laser_fit`自身824 B、`build`自身96 B、`sf_render`自身288 B。
これは個別関数の静的値であり、ライブラリ・割込みを含む実行時high-water markではない。
余裕を確保するためSDKの`PICO_STACK_SIZE`を4KiBにした。出力はbuild内の`.su`。
VRAMは既存の容量内。RTL資源の追加はない。
