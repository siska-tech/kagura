# PROJECT STARFALL 第4版 — 下部ゲージと基地侵入

2026-10-31、`feat/project-starfall`。診断firmware、MicroPython、RTLは変更していない。

## 変更点

1. パワーゲージ6枠を画面下の専用パネルへ移動。
   パネル先頭は`(height/8-3)*8`、アイコンはそこから4px下。
   480pではy220、720pではy156。自機・敵・弾・カプセルをplay area内へ制限し、
   爆発はパネルに掛かる場合だけ省略する。レーザーの透明部分も含めてscanline数を検査する。
2. ミサイルは水平0.5px/tick、初速下向き1px/tickから加速し最大4px/tickで落下。
   着地後は横向きへ変わって5px/tickで床を進む。発射直後から横に流れていた動きを改めた。
   宇宙には床がないため、play areaの下へ落ちて消える。地形・HUDへ貼り付かない。
3. 世界座標で空中戦→基地入口→基地内部→ボス格納庫を生成する。
   同じ座標関数をmap生成、衝突、ミサイル、敵の移動制限で共有する。

| 進行 | 内容 |
|---|---|
| 0〜約18.7秒 | 壁・固定砲台なし、宇宙で敵編隊と戦闘 |
| 約18.7〜24秒 | world x1440の基地入口が右端から近づく |
| 24〜約44秒 | 金属パネル、梁、警戒ストライプ、上下の隆起、壁面砲台 |
| 約44秒以降 | 広い格納庫へ進み、警告→46秒中ボス |
| 60秒以降 | ボス撃破済みならclear、未撃破なら戦闘続行 |

宇宙では中央星空の1/3速rasterを維持し、入口が見える時点で通常scrollへ揃える。
これにより基地の表示座標と衝突座標を同一にする。未選択時の上段HUDはSPACE/ENTRY/BASE。
素材と音楽はオリジナルのまま。

## Mapストリーミングと同期

64×32 mapをringとして使う。スクロールが8px進むたび、現在の左端tileから63列先を更新する。
画面は40〜41列なので、対象は画面右端のさらに約23列先であり、表示中の列ではない。
低位byte32個を`INC=128`で1トランザクションにまとめる（全tile番号は0..255）。
map属性の上位byteとtile bit10は起動時の0を維持する。
更新はVBlankで行い、sprite/scrollはCOMMITで反映する。全画面pixel転送は行わない。

通常は32 B/8tick、平均4 B/tickのmap payloadが加わる。
再スタート時だけ表示停止→初期map4096 B→FENCE→表示再開で宇宙へ戻す。
この時は短時間黒画面となり、処理時間は通常frameとは区別すべきである。
`map_bytes`はmap payload累計（再開時4096 Bを含む）。`wire_*`は従来どおり全通信を含む。

## 予算・検証

| 項目 | 結果 |
|---|---:|
| Pattern / 公開VRAM予約計 | 256個8192 B / 15200 B（前版と同じ） |
| 管理OAM | 64枠512 B、最悪16 sprite/scanline |
| ゲーム状態 / 描画frame | 608 / 520 B（ホスト） |
| ELF text / data / bss | SPI/QSPIとも80992 / 0 / 15264 B |
| UF2 | 各154112 B |

stack high-water mark・実機転送速度は未測定。
ホストはC11、Wall/Wextra/Werror、ASan/UBSan。3件PASS:

- ゲーム: 各解像度216000tickの決定的replay、全武器＋支援機＋missileの通し運転、
  実弾によるボス破壊/clear。地形512列のmapと衝突一致、下部ゲージ位置、
  床近くで16 spriteが集まった場合のゲージ分離、落下距離/横移動量/宇宙での消滅も検査。
- backend: 180/240両方で4000tick分のring更新を模擬。転送先が現在の40〜41列と
  重ならないこと、全表示列の32行と生成元の一致、map high byte=0、転送失敗時順序、
  raster切替、再スタートで初期宇宙mapへ戻ることを検査。
- controller: 6bit入力、Shift併用、focus/終了時の解除。

通し運転のボス試験は観測用に無敵を補充しており、人間によるクリアや難易度の確認ではない。
参照画像（宇宙・入口・基地・落下・レーザー・ボス）をソフトウェア合成して目視確認。
実機での新版fps・転送量・遊びやすさ・長時間動作は未検証。
RTL変更はなく、全RTL回帰/合成/STAは今回実施していない。
