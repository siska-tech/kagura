# PROJECT STARFALL 第3版 — 装備選択と武器

2026-10-31。ブランチ`feat/project-starfall`。既存の診断・MicroPython・RTLは変更なし。

## プレイの変更

カプセルは装備を自動付与せず、6枠のゲージを1つ進める。
SPEED → MISSILE → DOUBLE → LASER → OPTION → SHIELD → SPEEDと循環し、
X/Shift（GPIO GP16）を押した瞬間に選んだ装備を発動する。正常発動で選択は0へ戻る。
取得上限や同じ主武器の再取得では選択を消費しない。橙は選択中、緑は取得済み。
HUDと地形に合わせ、自機の上限をy=40へ変更した。

| 装備 | 仕様 |
|---|---|
| SPEED | 1回ごとに0.5px/tick増速、3段階まで。斜め速度補正あり |
| MISSILE | FIRE連動の副武装、1発。下降後に床の高さを追従、命中2damage |
| DOUBLE | 水平と斜め上の交互射撃、1damage。LASERとは排他 |
| LASER | 64pxの移動パルス、1本、敵を貫通し各敵に1回3damage |
| OPTION | 履歴ring追従、2機。自機・支援機の発射元を順番に使う |
| SHIELD | 3回吸収、吸収ごと45tick無敵。機体の配色で有無を示す |

レーザーは4個の16×16 sprite。地形と画面端で長さを切る。
1..16px幅のパターンを用意して端のsprite自体も短くし、壁の向こうに光だけ残さない。
命中履歴は敵poolのslot番号と生成serialで管理するため、同じ敵への重複ダメージを防ぎ、
同slotに後から出た別の敵には命中できる。

編隊データを15個のwave記述（開始tick/type/lane/count/gap）へ整理した。
飛行敵は1発で倒せ、先頭の橙色リーダーを撃破するとカプセルが出る。
全機撃破はさらに500点とカプセル。逃した機体やpool不足で省略された機体があるwaveは
全滅ボーナスを付けない。カプセルは表示1個、追加分を最大8個まで待機する。
序盤の最初の編隊を中央へ配置し、通常ショットで強化の足掛かりを作れるようにした。
上下の地形は段階的な隆起へ調整。機体・曲・敵の意匠は引き続きオリジナル。

## ハードウェア予算

| 項目 | 値 |
|---|---:|
| Pattern | 256×32 = 8192 B、番号0..255、16×16 blockは4整列 |
| Map / upper表 | 4096 / 256 B |
| Palette | 3本×16色 = 96 B |
| OAM予約 | 2048 B、管理するのは64枠512 B |
| Wave | 512 B、両bank同一初期化 |
| 公開VRAM予約計 | 15200 B |
| 静的SRAM bss | 15240 B（SDK/USBを含む、stack high-water markは未測定） |
| ゲーム状態 / frame | 604 / 520 B（ホスト検査） |
| ELF text / data | 77152 / 0 B、SPI/QSPIとも同値 |

最大同一lineは、自機1＋通常弾4（またはレーザー4segment）＋敵4＋敵弾3＋
ミサイル1＋カプセル1＋支援機2=16。
ミサイル追加分は敵弾poolを4→3へ変更して確保した。ボスは通常敵と同居せず、
各lineで2sprite。爆発だけを必要に応じて省略し、危険な弾や敵を隠さない。

ゲージ6spriteはy16..31、自機/支援機/レーザー/敵弾はy40以降。
この帯へ来る斜め弾4＋壁面砲台4を含めても6+4+4=14。
上段の数値と選択名はy8、最大16文字。rendererは全240lineを実際に積算する。
BG/patternは起動時のみuploadし、実行中はshadow OAMと既存registerだけを更新する。
前版のVBlank同期、差分run、COMMIT待ちpollの間引き、待機中のログ出力は維持する。

## 検証

- C11、Wall/Wextra/Werror、ASan/UBSanでホスト3件PASS。
- 180/240各216000stepの決定的replay、実弾によるボス撃破/clear。
- 全6装備、選択上限、ゲージ循環、キー長押し、被弾リセット、盾3回吸収。
- 複数敵への貫通、1敵1回ダメージ、敵slot再利用、地形/端pixelのレーザーclip。
- 全64列の床に対するmissile追従、砲台破壊、全滅/逃走による報酬差。
- 各主武器＋支援機2＋missileで4000stepを通し、最大16/lineを確認。
- USB controllerは実スクリプトをfake Tk/serialで実行。6bit全入力、Shift+Wと
  修飾キー解除後のkey-up、focus loss、終了時の解除packetを検査。
- backend mockで起動asset、VBlank、差分転送、エラー時順序、音源/rasterを検査。
- 生成register照合と既存設計チェックPASS。RTLは変更せず、全RTL回帰/合成/STAは未実施。

ホスト通し試験は観測用に無敵時間を補充する。人間の難易度確認や実機連続運転の代替ではない。
参照画像は実タイル/OAMのソフトウェア合成であり、実機写真ではない。
実機でのfps・転送量・音量・難易度・新しい操作系は未検証。
