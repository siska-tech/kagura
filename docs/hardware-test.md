# 実機試験の手順と記録

HDMIの実機互換性と連続動作の受入試験。受入条件は**2機種以上のsink×2本のケーブルで、起動20回・抜挿10回・各1時間**、全対象で映像と左右の音声が正常、通常動作でerror 0。計測器のない項目は未測定と記録し、simulationの証拠と混ぜない。

## 機材

| ID | 種別 | 型番 | 状態 |
|---|---|---|---|
| B1 | FPGA基板 | Tang Nano 9K（シルク3674、GW1NR-LV9QN88PC6/I5、chip ID `0x1100481B`） | 1台 |
| S1 | HDMI sink | MSI MAG 325CQRF-QD（31.5インチ PCモニター） | 480p/720pで映像・音声を確認済み |
| S2 | HDMI sink | TOSHIBA REGZA 32S5（テレビ） | 480p/720pで確認済み |
| S3 | HDMI sink | TCL製テレビ 43V型 | 480pで無信号。合否判定の対象外（原因調査用） |
| C1, C2 | HDMIケーブル | 2m×2本（型番未記録） | |
| H1 | SPI/QSPI host | Raspberry Pi Pico（RP2040） | 5MHzで診断合格 |
| M1 | オシロスコープ | Siglent SDS1202X-E（200MHz・2ch） | |
| U1 | CPU | W65C02S（3.3V） | 未調達 |

試験記録には機材IDを使い、sinkの入力端子と画質・音声の設定（ゲームモード等）も書く。電源（PCのUSBポート/USB電源）も記録する。

## 対象bitstream

各bitstreamは`tools/run-baseline.ps1`または[ビルド手順](build-and-test.md)で作り、書込んだ`.fs`のSHA256とsource commitを記録する。

| 段階 | 構成（`.fs`） | 映像・音声 | 範囲 |
|---|---|---|---|
| A | `hdmi`（`kagura_phase1.fs`）、`hdmi720`（`kagura_hdmi720.fs`） | カラーバー＋白枠、左1kHz・右500Hz | 必須。4組合せ×（起動20・抜挿10・1時間） |
| B | `demo`（`kagura_demo.fs`）、`demo720`（`kagura_demo720.fs`） | シューティング画面が毎フレーム動き、6ch演奏 | 必須。各sink×1本以上で起動5・抜挿3・1時間。残りの組合せは起動5 |
| C | `qspipsram`/`qspipsram720`＋Pico `stress 3600` | 256 spriteと多重scroll、PSG＋PCM、毎フレームCOPY | 各sinkで1時間 |

段階B・Cは描画と音源を動かし続ける状態の確認で、段階Aの代わりにはならない。起動回数は内蔵Flash（`--run 6`）から行う。1時間試験はSRAM書込みでもよい（その旨を記録する）。

## 判定基準

LEDの意味は[アーキテクチャ](architecture.md#led)。

| 記号 | カラーバー版 | demo版 | 段階C |
|---|---|---|---|
| V | 8色のバーが左から白・黄・シアン・緑・マゼンタ・赤・青・黒 | 背景がscrollし、自機・敵が動く | 花びら（sprite）と背景が動く |
| B | 1画素の白枠が上下左右の4辺とも見える | 画面端の欠け・ずれなし | HUDの文字が欠けない |
| A | 左が高い音、右が低い音。途切れ・ノイズなし | 曲が途切れずに鳴る | 旋律と打楽器が途切れずに鳴る |
| L | LED1・5・6点灯、LED2〜4消灯 | LED1・5・6点灯、LED2点滅、LED3消灯 | LED1・5・6点灯、LED2〜4消灯、`STRESS PASS` |

underflow・overflow・`late`のLEDはresetまで点灯を保持するので、1時間後に消灯していればその間の発生は0回（回数は数えられない）。demo版のLED4は編隊がline上限を超える区間で点灯するのが正常。

## 手順（sink×ケーブルの組合せごと）

1. **起動**: USBを抜いて5秒以上待ち、挿す。Flashから起動して映像が出るまでの時間とV/B/A/Lを確認する。sinkの電源は入れたまま。
2. **抜挿**: 動作中にHDMIケーブルをsink側で抜き、5秒以上待って挿す。映像と音声が戻るか、V/B/A/Lを確認する。
3. **reset復帰（各組合せ1回以上）**: S2（pin 4）を押している間はmute（カラーバー版はLED2点灯）、離すと映像・音声が戻ることを確認する。demo版は曲頭と画面の初期状態へ戻る。
4. **1時間連続**: 開始時刻を記録して放置し、1時間後にV/B/A/Lを確認する。途中の画面消失・音切れは時刻を記録する。段階CはPicoの最終行も記録する。

### 720pのreset反復

`hdmi720`について、各sink×ケーブル1本以上でS2を20回押して離す。押下は1秒以上保持し、復帰を確認してから次へ進む。各回で720pとしての再認識、色ずれ・横ずれ・lane欠落がないことを確認する。手操作の解除位相は371.25MHzに同期しないため複数の位相を通るが、全位相の網羅ではない。

旧方式（lane別fabric RESET）のbitstreamでは、2026-10-24にS1×C1・S2×C1で各20/20合格した。現在のchip GSR版では未実施。

## 範囲外

- カラーバー版の音は固定のtest toneなので、入力停止時の無音挿入と復帰は実機では起こせない。simulationの証拠は`tb_hdmi_stream`。
- 周波数・jitter・TMDSの電気特性・sinkが受け取ったInfoFrameの内容は計測器がなく未測定。
- S3（TCL）の無信号は、同じ電源・ケーブル・入力でSipeed公式サンプルとKAGURAを比べ、条件を1つずつ変えて調べる。受入試験とは別に記録する。
